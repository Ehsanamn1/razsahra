# چک‌لیست پیش از خرید هاست میزبان‌فا — راز صحرا + مدار

این سند برای جلوگیری از خرید پلن نامناسب است. تا زمانی که پلن و دسترسی واقعی هاست مشخص نشده، هیچ انتشار روی هاست میزبان‌فا انجام‌شده محسوب نمی‌شود.

## متن آماده برای پشتیبانی پیش از خرید

سلام. قصد دارم وب‌سایت فارسی Node.js به همراه پنل مدیریت محتوا و رابط مدار در مسیر `/madar/` را روی سرویس شما اجرا کنم. لطفاً قبل از خرید، پاسخ کتبی این موارد را اعلام کنید:

1. آیا پلن موردنظر اجرای برنامه سفارشی Node.js نسخه 20 یا 22 را پشتیبانی می‌کند؟
2. آیا اجرای برنامه با Passenger یا روش رسمی مشابه، تنظیم مسیر App Root، فایل شروع `server.js` و restart/restart-on-deploy پشتیبانی می‌شود؟
3. آیا MySQL 8، ساخت دیتابیس و کاربر مستقل، و دسترسی اتصال از برنامه Node.js به دیتابیس همان حساب پشتیبانی می‌شود؟
4. آیا متغیرهای محیطی محرمانه از پنل قابل تنظیم‌اند، بدون آنکه در فایل‌های عمومی یا Git قرار گیرند؟
5. آیا برنامه اجازه درخواست HTTPS خروجی به API مدار در Cloudflare Workers را دارد؟
6. آیا گواهی SSL برای دامنه و زیردامنه، لاگ خطا، بکاپ قابل‌بازیابی و فضای کافی برای فایل‌های build و وابستگی‌های production ارائه می‌شود؟
7. آیا SSH/SFTP برای استقرار خودکار از GitHub Actions وجود دارد؟ اگر SSH ندارید، روش رسمی و قابل‌تکرار به‌روزرسانی فایل‌ها و راه‌اندازی مجدد برنامه چیست؟
8. محدودیت RAM، CPU، تعداد process، زمان اجرای برنامه، فضای دیسک، پهنای باند و محدودیت اتصال دیتابیس چقدر است؟
9. آیا امکان تست برنامه قبل از اتصال دامنه اصلی وجود دارد (دامنه موقت یا subdomain)؟

لطفاً نام دقیق پلن و محدودیت‌های آن را نیز مشخص کنید. اگر اجرای Node.js دائمی یا اتصال خروجی HTTPS پشتیبانی نمی‌شود، این پلن برای این بسته مناسب نیست.

## معماری فعلی بسته

- فایل‌های فرانت‌اند راز صحرا و مدار در بسته استقرار آماده شده‌اند.
- CMS و endpointهای این بسته برای استقرار Node.js/MySQL در نظر گرفته شده‌اند.
- **API عملیاتی مدار هنوز از طریق `MEDAR_API_ORIGIN` به Worker فعلی Cloudflare متصل است.** بنابراین این بسته تمام وابستگی مدار به Cloudflare را حذف نمی‌کند.
- بسته هیچ رمز واقعی، فایل `.env`، `node_modules` یا اطلاعات ورود به هاست را در خود ندارد.

## پس از خرید

1. پلن را فقط پس از تأیید موارد بالا تهیه کنید.
2. از پنل، دسترسی برنامه Node.js، دیتابیس MySQL و دامنه/SSL را فعال کنید؛ رمزها را در چت ارسال نکنید.
3. اطلاعات غیرمحرمانه اتصال (نوع اجرا، نسخه Node، مسیر App Root و روش restart) را ثبت کنید و مقادیر محرمانه را فقط در پنل هاست یا GitHub Secrets وارد کنید.
4. مقادیر `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `ADMIN_BOOTSTRAP_SECRET` و `MEDAR_API_ORIGIN` را مطابق مستندات بسته تنظیم کنید.
5. ابتدا روی دامنه موقت، schema و preflight را اجرا و مسیرهای سلامت، ورود مدیر، فرم همکاری و مسیرهای مدار را تست کنید.
6. پس از موفقیت تست پذیرش، دامنه اصلی را متصل کنید و بکاپ و روش rollback را تأیید کنید.

## اتوماسیون GitHub

اتوماسیون فعلی فقط **preflight غیرمخرب** است؛ workflow انتشار production عمداً فعال نشده است. اتوماسیون deploy فقط وقتی قابل تکمیل و تست واقعی است که میزبان روش رسمی SSH یا روش استقرار غیرتعاملی قابل پشتیبانی را تأیید کند. در صورت تأیید SSH، مقادیر اتصال باید به‌عنوان GitHub Actions Secrets تنظیم شوند؛ برای مثال:

- `HOST_SSH_HOST`
- `HOST_SSH_PORT`
- `HOST_SSH_USER`
- `HOST_SSH_PRIVATE_KEY`
- `HOST_SSH_KNOWN_HOSTS` (host-key fingerprint verified from HostMizbanFa; do not blindly trust `ssh-keyscan` output)
- `HOST_APP_DIR`
- `HOST_HEALTH_URL`

این نام‌ها فقط قالب‌اند؛ تا پیش از دریافت اطلاعات واقعی نباید برایشان مقدار حدسی ثبت کرد. workflow نهایی باید پس از موفقیت CI اجرا شود، پیش از جایگزینی نسخه قبلی بکاپ بگیرد، فایل `.env` را حفظ کند، وابستگی‌های production را نصب کند، برنامه را restart کند و endpoint سلامت را بررسی کند. اجرای خودکار تغییرات دیتابیس باید جدا و کنترل‌شده باشد؛ نباید در هر deploy بدون بررسی اجرا شود.

## تعریف آمادگی

- **آماده برای نصب:** بسته و دستورالعمل‌ها آماده‌اند.
- **آماده برای انتشار خودکار:** تا وقتی روش deploy میزبان مشخص و workflow ساخته/تست نشده، تأیید نشده است.
- **بدون باگ:** قابل تضمین نیست؛ فقط می‌توان با CI، تست روی هاست واقعی، آزمون پذیرش و پایش پس از انتشار ریسک را کاهش داد.
