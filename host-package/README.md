# بستهٔ استقرار راز صحرا + مدار — Node.js / MySQL

## وضعیت انتشار
این بسته اکنون شامل وب‌سایت راز صحرا و رابط وب مدار در مسیر `/madar/` است. سرور Node مسیر `/api/medar/*` را به API عملیاتی مدار که در `MEDAR_API_ORIGIN` تنظیم می‌شود پروکسی می‌کند تا کوکی نشست مرورگر same-origin بماند.

**محدودیت مهم:** API عملیاتی مدار هنوز به Node/MySQL منتقل نشده است و برای ورود و عملیات مدار به Worker عملیاتی و دیتابیس متصل به آن وابسته است. بنابراین این بسته انتشار مستقل و بدون Cloudflare نیست. انتشار نهایی روی میزبان‌فا نیز تا اجرای آزمون پذیرش واقعی روی همان هاست تأیید نشده است.

## نیازمندی‌ها
- Node.js 20 یا بالاتر
- MySQL 8 با مجوز ایجاد جدول و خواندن/نوشتن
- امکان اجرای دائمی برنامه Node از پنل هاست (Node.js 20+؛ این قابلیت باید در پلن مشخص میزبان‌فا تأیید شود)
- دامنه با HTTPS
- دسترسی شبکهٔ خروجی سرور به `MEDAR_API_ORIGIN`

## نصب
**دروازهٔ سازگاری میزبان‌فا:** پیش از بارگذاری، در پنل بررسی کن بخش Node.js Application / Application Manager یا Passenger وجود داشته باشد و Node.js نسخهٔ ۲۰ یا بالاتر را اجرا کند. صرف داشتن هاست لینوکس/cPanel به معنی پشتیبانی از اجرای Express نیست. اگر این قابلیت در پلن تو وجود ندارد، این بسته را نمی‌توان با آپلود ساده در `public_html` اجرا کرد؛ باید از پشتیبانی میزبان‌فا فعال‌بودن Node.js و امکان اجرای برنامهٔ دائمی را تأیید بگیری یا از پلن سازگار استفاده کنی.

1. فایل ZIP را در پوشهٔ برنامه استخراج کن؛ محتوای `dist/` باید همراه `dist/madar/` باقی بماند.
2. یا متغیرهای `.env.example` را در بخش Environment Variables پنل هاست تنظیم کن، یا فایل را به `.env` تغییر نام بده و مقدارها را در آن وارد کن. سرور این فایل را می‌خواند؛ فایل واقعی `.env` را در Git یا ZIP عمومی قرار نده.
3. `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` را با دیتابیس ایجادشده در پنل میزبان پر کن.
4. `MEDAR_API_ORIGIN` را روی مبدأ HTTPS سرویس عملیاتی مدار تنظیم کن؛ فقط scheme و host، بدون مسیر یا credential.
5. در پوشهٔ برنامه `npm install --omit=dev` و سپس `npm run install:db` را اجرا کن.
6. پیش از راه‌اندازی، `npm run preflight` را اجرا کن. این فرمان Node.js، اتصال و جدول‌های MySQL و سلامت API عملیاتی مدار را بررسی می‌کند.
7. برنامه را با `npm start` اجرا کن و `/api/health` را بررسی کن.
8. برای مدیر اولیه یک `ADMIN_BOOTSTRAP_SECRET` تصادفی حداقل ۳۲ نویسه‌ای تنظیم کن. درخواست bootstrap را فقط یک‌بار و از مبدأ معتبر اجرا کن؛ پس از ایجاد مدیر، secret را از تنظیمات هاست حذف کن.
9. آزمون‌های پذیرش پایین را کامل کن؛ قبل از آن این بسته را برای عملیات واقعی اعلام‌شده آماده ندان.

## مسیرهای پذیرش
- `/api/health` — اتصال MySQL
- `/api/auth/bootstrap-admin`, `/api/auth/login`, `/api/auth/me`, `/api/auth/logout` — مدیریت نشست CMS
- `/api/admin/overview`, صفحات، مقاله‌ها، کاربران، پیام‌ها، برنامه‌ها و تنظیمات — CMS
- `/madar/` و `/madar/app/home` — رابط و deep-link مدار
- `/api/medar/api/health` و ورود مدار — پروکسی به API عملیاتی
- آزمون نقش‌ها و مجوزها با حساب‌های staging
- فرم تماس، ثبت درخواست و دریافت آن در پیشخوان
- بررسی کوکی‌ها با HTTPS، راه‌اندازی مجدد برنامه و لاگ خطاها

## امنیت و محدودیت‌ها
- بررسی خودکار GitHub Actions اجرای Node.js را در محیط CI ثابت می‌کند؛ پشتیبانی Node.js پلن میزبان‌فا را ثابت نمی‌کند. این مورد فقط از پنل یا پشتیبانی میزبان‌فا قابل تأیید است.
- هرگز رمز، session token، `DATABASE_URL` یا کلیدهای Worker را در bundle فرانت‌اند قرار نده.
- endpoint bootstrap را پس از راه‌اندازی با حذف secret غیرفعال کن.
- schema از `CREATE TABLE IF NOT EXISTS` و seedهای `INSERT IGNORE` استفاده می‌کند؛ با این حال پیش از استقرار از دیتابیس مقصد backup قابل‌بازیابی بگیر.
- این بسته جایگزین انتقال کامل API مدار به Node/MySQL نیست. برای قطع وابستگی به Worker و PostgreSQL باید API مدار به‌طور کامل منتقل و جداگانه آزمون شود.
