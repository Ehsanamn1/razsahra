# بستهٔ استقرار راز صحرا + مدار — Node.js / MySQL

## وضعیت انتشار
این بسته اکنون شامل وب‌سایت راز صحرا و رابط وب مدار در مسیر `/madar/` است. سرور Node مسیر `/api/medar/*` را به API عملیاتی مدار که در `MEDAR_API_ORIGIN` تنظیم می‌شود پروکسی می‌کند تا کوکی نشست مرورگر same-origin بماند.

**محدودیت مهم:** API عملیاتی مدار هنوز به Node/MySQL منتقل نشده است و برای ورود و عملیات مدار به Worker عملیاتی و دیتابیس متصل به آن وابسته است. بنابراین این بسته انتشار مستقل و بدون Cloudflare نیست. انتشار نهایی روی میزبان‌فا نیز تا اجرای آزمون پذیرش واقعی روی همان هاست تأیید نشده است.

## نیازمندی‌ها
- Node.js 20 یا بالاتر
- MySQL 8 با مجوز ایجاد جدول و خواندن/نوشتن
- امکان اجرای برنامه Node.js از پنل هاست؛ طبق پاسخ پشتیبانی میزبان‌فا، اجرای Node.js 20+ روی هاست اشتراکی امکان‌پذیر است، اما تنظیمات و دسترسی‌های حساب باید در پنل بررسی شود
- دامنه با HTTPS
- دسترسی شبکهٔ خروجی سرور به `MEDAR_API_ORIGIN`

## نصب
**وضعیت میزبان‌فا:** طبق پاسخ پشتیبانی‌ای که دریافت شده، هاست اشتراکی میزبان‌فا امکان اجرای Node.js نسخهٔ ۲۰ یا بالاتر را دارد. با این حال، برنامه باید از بخش مدیریت برنامه‌های Node.js/Passenger در پنل همان حساب ساخته و اجرا شود؛ صرف استخراج فایل‌ها داخل `public_html` کافی نیست. پس از دریافت دسترسی پنل، نسخهٔ Node و مسیر اجرای برنامه را در همان حساب بررسی کن.

1. فایل ZIP را در پوشهٔ برنامه استخراج کن؛ محتوای `dist/` باید همراه `dist/madar/` باقی بماند.
2. یا متغیرهای `.env.example` را در بخش Environment Variables پنل هاست تنظیم کن، یا فایل را به `.env` تغییر نام بده و مقدارها را در آن وارد کن. سرور این فایل را می‌خواند؛ فایل واقعی `.env` را در Git یا ZIP عمومی قرار نده.
3. `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD` را با دیتابیس ایجادشده در پنل میزبان پر کن.
4. `MEDAR_API_ORIGIN` را روی مبدأ HTTPS سرویس عملیاتی مدار تنظیم کن؛ فقط scheme و host، بدون مسیر یا credential.
5. در پوشهٔ برنامه `npm install --omit=dev` و سپس `npm run install:db` را اجرا کن.
6. پیش از راه‌اندازی، `npm run preflight` را اجرا کن. این فرمان Node.js، اتصال و جدول‌های MySQL و سلامت API عملیاتی مدار را بررسی می‌کند.
7. در پنل مدیریت برنامه‌های Node.js/Passenger، فایل شروع را `app.js` قرار بده؛ سپس برنامه را اجرا کن و `/api/health` را بررسی کن.
8. برای مدیر اولیه یک `ADMIN_BOOTSTRAP_SECRET` تصادفی حداقل ۳۲ نویسه‌ای تنظیم کن. درخواست bootstrap را فقط یک‌بار و از مبدأ معتبر اجرا کن؛ پس از ایجاد مدیر، secret را از تنظیمات هاست حذف کن.
9. آزمون‌های پذیرش پایین را کامل کن؛ قبل از آن این بسته را برای عملیات واقعی اعلام‌شده آماده ندان.

## استقرار خودکار با GitHub Actions

بعد از تنظیم اولیهٔ حساب میزبان‌فا، انتشار تغییرات کد از شاخهٔ `main` به‌صورت خودکار انجام می‌شود. workflow ابتدا سایت و رابط مدار را می‌سازد، تست‌های CI و تست‌های MySQL موقت را اجرا می‌کند؛ فقط اگر این مراحل موفق باشند و متغیر `HOST_DEPLOY_ENABLED` در GitHub برابر `true` باشد، فایل‌ها را با SSH به برنامه می‌فرستد، برنامه را restart می‌کند و مسیرهای واقعی را تست می‌کند. هنگام شکست تست پس از انتشار، بازگردانی فایل‌های نسخهٔ قبلی تلاش می‌شود.

### تنظیم یک‌بارهٔ GitHub (بعد از تهیه و راه‌اندازی هاست)

در Settings → Secrets and variables → Actions، این موارد را ثبت کن:

**Repository variables**
- `HOST_DEPLOY_ENABLED` = `true` — فقط پس از عبور preflight و آماده‌بودن دامنه فعال شود.
- `HOST_APP_DIR` = مسیر مطلق پوشهٔ اختصاصی برنامه داخل home حساب SSH، مانند `/home/ACCOUNT/razsahra-app`؛ مسیر واقعی را از پنل/پشتیبانی بگیر و نمونهٔ فرضی را کپی نکن.
- `HOST_HEALTHCHECK_URL` = مبدأ HTTPS دامنه، مانند `https://razsahra.ir`، بدون مسیر اضافه.

**Repository secrets**
- `HOST_SSH_HOST`
- `HOST_SSH_PORT`
- `HOST_SSH_USER`
- `HOST_SSH_PRIVATE_KEY`
- `HOST_SSH_KNOWN_HOSTS` — کلید میزبان را فقط پس از تأیید fingerprint رسمی میزبان‌فا ذخیره کن.

این گردش‌کار در هاست به SSH و دستورهای Node.js، npm، tar، unzip، curl و rsync نیاز دارد؛ preflight همهٔ موارد را قبل از فعال‌سازی استقرار بررسی می‌کند. مقادیر اتصال SSH فقط در GitHub Secrets می‌مانند؛ رمز دیتابیس و `ADMIN_BOOTSTRAP_SECRET` باید فقط در محیط برنامهٔ میزبان‌فا بمانند، نه در GitHub و نه در بستهٔ انتشار. اپ Node را یک‌بار در پنل ایجاد کن، مسیر startup را روی `app.js` قرار بده و متغیرهای محیطی/اتصال MySQL را تنظیم کن. دیتابیس و مدیر اولیه هم فقط یک‌بار مقداردهی می‌شوند. سپس workflow موجود `HostMizbanFa connection preflight` را اجرا کن؛ این کار قبل از فعال‌سازی deploy باید بدون تغییر دیتابیس یا فایل‌های برنامه موفق شود.

### بعد از تنظیم اولیه

- هر تغییر کدی که از CI عبور کند و به `main` برسد، با همان pipeline روی Cloudflare Pages هم منتشر می‌شود و اگر `HOST_DEPLOY_ENABLED=true` باشد، روی میزبان‌فا نیز خودکار مستقر می‌شود.
- فایل `.env`، `.htaccess`، `node_modules`، پوشهٔ `tmp` و داده‌های uploads در انتقال عادی جایگزین یا پاک نمی‌شوند؛ dependencyها طبق lockfile نصب و Passenger با `tmp/restart.txt` بازراه‌اندازی می‌شود.
- پیش از جایگزینی، نسخهٔ کد موجود در home حساب backup می‌شود. اگر smoke test دامنه، MySQL، مدار یا حفاظت API مدیریت شکست بخورد، workflow تلاش می‌کند کد قبلی را برگرداند؛ backupها بیرون از پوشهٔ برنامه ذخیره می‌شوند.
- تغییرهای عادی رابط، ظاهر و منطق برنامه نیازی به ورود به پنل دیتابیس ندارند. تغییرات schema یا تبدیل داده‌ها مسیر جداگانهٔ migration، backup و تست می‌خواهد؛ pipeline به‌طور خودکار schema دیتابیس واقعی را تغییر نمی‌دهد.
- تا زمانی که هاست خریداری و secrets/variables بالا ثبت نشده‌اند، انتشار خودکار میزبان‌فا عمداً خاموش می‌ماند؛ Cloudflare Pages مستقل به کارش ادامه می‌دهد.

## مسیرهای پذیرش
- `/api/health` — اتصال MySQL
- `/api/auth/bootstrap-admin`, `/api/auth/login`, `/api/auth/me`, `/api/auth/logout` — مدیریت نشست CMS
- `/api/admin/overview`, صفحات، مقاله‌ها، کاربران، پیام‌ها، برنامه‌ها و تنظیمات — CMS
- `/madar/` و `/madar/app/home` — رابط و deep-link مدار
- `/api/medar/api/health` و ورود مدار — پروکسی به API عملیاتی
- آزمون نقش‌ها و مجوزها با حساب‌های staging
- فرم تماس، ثبت درخواست و دریافت آن در پیشخوان
- بررسی کوکی‌ها با HTTPS، راه‌اندازی مجدد برنامه و لاگ خطاها

## امنیت و محدودیت‌ها
- پشتیبانی میزبان‌فا امکان اجرای Node.js 20+ روی هاست اشتراکی را اعلام کرده است؛ با این حال، سلامت نهایی فقط پس از تنظیم برنامه و اجرای آزمون‌ها روی دامنه واقعی تأیید می‌شود.
- هرگز رمز، session token، `DATABASE_URL` یا کلیدهای Worker را در bundle فرانت‌اند قرار نده.
- endpoint bootstrap را پس از راه‌اندازی با حذف secret غیرفعال کن.
- schema از `CREATE TABLE IF NOT EXISTS` و seedهای `INSERT IGNORE` استفاده می‌کند؛ با این حال پیش از استقرار از دیتابیس مقصد backup قابل‌بازیابی بگیر.
- این بسته جایگزین انتقال کامل API مدار به Node/MySQL نیست. برای قطع وابستگی به Worker و PostgreSQL باید API مدار به‌طور کامل منتقل و جداگانه آزمون شود.
