# وضعیت استقرار راز صحرا + مدار روی میزبان‌فا

## وضعیت واقعی در تاریخ این بررسی

- بستهٔ فعلی شامل وب‌سایت راز صحرا، CMS مبتنی بر Node.js/MySQL، رابط وب مدار در مسیر /madar/ و proxy مسیر /api/medar/* است.
- ساخت بسته و آزمون‌های CI در GitHub انجام می‌شوند.
- API عملیاتی مدار هنوز به Node.js/MySQL منتقل نشده است؛ عملیات ورود و دادهٔ مدار همچنان به Worker عملیاتی و دیتابیس خارجی متکی است.
- بسته هنوز روی حساب واقعی میزبان‌فا نصب یا پذیرش نشده است.
- طبق پاسخ پشتیبانی میزبان‌فا، پلن اشتراکی فعلی SSH برای GitHub Actions، دسترسی root و اتصال ریموت دیتابیس ندارد؛ تحویل فایل از File Manager انجام می‌شود.

## کارهایی که از راه دور می‌توان آماده کرد

1. ساخت و تست بستهٔ ZIP در GitHub Actions.
2. نگهداری سورس و راهنمای نصب در مخزن.
3. تست‌های نرم‌افزاری و health-checkهای مستقل از حساب میزبان.
4. تولید بستهٔ staging پس از تکمیل و تست مهاجرت واقعی API مدار.

## کارهایی که هنوز روی حساب میزبان باید انجام شوند

1. دریافت مسیر/تنظیمات دقیق سرویس از cPanel.
2. تهیهٔ Full Backup قابل بازیابی قبل از تغییرات.
3. ایجاد برنامهٔ Node.js از مسیر cPanel → Setup Node.js App و انتخاب app.js، پس از آنکه بستهٔ نهایی و کامل تأیید شد.
4. ایجاد دیتابیس و کاربر MySQL اختصاصی و قراردادن secrets فقط در Environment Variables یا خارج از مسیر عمومی.
5. استخراج بستهٔ تأییدشده در مسیر برنامه، نصب وابستگی‌ها طبق روش مجاز پنل و راه‌اندازی برنامه.
6. آزمون مستقیم /api/health، صفحات عمومی، CMS، /madar/، deep-linkها، احراز هویت، ذخیره داده، restart و restore.
7. بررسی SSL و رکوردهای DNS روی آدرس آزمایشی؛ تغییر رکورد A دامنه فقط پس از عبور پذیرش نسخهٔ جدید.

## تحویل و به‌روزرسانی

- workflow استقرار SSH موجود برای پلن فعلی میزبان‌فا مناسب نیست. HOST_DEPLOY_ENABLED را روشن نکن و برای این حساب SSH secrets نساز.
- GitHub Actions می‌تواند build/test و تولید artifact را انجام دهد؛ انتقال فایل به حساب فعلی طبق پاسخ میزبان‌فا دستی از File Manager انجام می‌شود.
- انتشار هر تغییر جدید به سایت زنده را قبل از backup، تأیید بسته و آزمون روی نسخهٔ staging انجام نده.

## معیارهای پذیرش پیش از تغییر دامنه

- [ ] نسخهٔ جدید از HTTPS باز می‌شود.
- [ ] /api/health اتصال دیتابیس صحیح را تأیید می‌کند.
- [ ] ورود و خروج مدیر CMS، محافظت API مدیریت و ذخیرهٔ فرم‌ها کار می‌کنند.
- [ ] /madar/ و /madar/app/home پس از refresh قابل بارگذاری‌اند.
- [ ] API عملیاتی مدار و role/tenant checks بدون وابستگی خارجی لازم کار می‌کنند؛ در غیر این صورت وابستگی‌ها به‌وضوح ثبت می‌شوند.
- [ ] backup/restore و راه‌اندازی مجدد برنامه آزمایش شده‌اند.
- [ ] رکوردهای MX, SPF, DKIM, DMARC و سایر رکوردهای DNS قبل از تغییر ثبت شده‌اند.

## محدودیت‌های باقی‌مانده

این فایل گزارش آمادگی است، نه اعلام استقرار کامل. انتقال بک‌اند عملیاتی مدار، تبدیل و تطبیق داده‌های Neon/PostgreSQL، آزمون پذیرش روی حساب میزبان و هرگونه تغییر DNS هنوز انجام‌شده تلقی نمی‌شوند. تا اتمام این موارد، Cloudflare/Neon را حذف یا دامنهٔ زنده را جابه‌جا نکن.
